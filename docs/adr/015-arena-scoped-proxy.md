# ADR 015：Arena 专用代理与解析边界

日期：2026-10-05。目标保持 DSH Desktop 0.2.0-rc.2 / Cordis 4.0.4。

## 实证与决策

本机系统 DNS 对 `huggingface.co` 返回异常的 IPv4 / Teredo 地址；原有直连校验正确拒绝部分答案，另一些请求连接超时。Arena 的四个子榜共用同一数据集读取器，版本入口失败会同时标记四项失败。现有 macOS HTTP 代理 `127.0.0.1:7897` 可正常读取同一个官方数据集，未提供任何站点凭据。

已核对目标版本的开发入门、架构、代理指南、`@deepseek-ai/dsh-http-proxy` 公共 exports / README 与 `dsh-web-fetch-http` 的代理分支。DSH 不自动读取操作系统代理，私有 Agent 也不会继承全局 dispatcher。为只处理用户指定的 Arena，不写 `$DSH_HOME/.env`、不安装全局 dispatcher，也不修改系统 DNS 或代理规则。

新增插件设置 `leaderboard.arenaProxyUrl`，默认 null（直连）；旧配置通过现有 schema 补 null，不新增 SQLite 迁移，不更改历史 checksum。后台可选模块提供明确输入。仅接受不带账号密码、查询参数或路径的 HTTP(S) 代理 origin，避免把秘密存进普通设置。

Arena 的 Hugging Face 原始请求使用该显式代理，后续官方 CDN 重定向沿用同一代理所有者。其他来源、新闻采集、模型和付费服务继续使用原有网络路径。代理由当前任务持有，受任务 / 模块取消信号约束，抓取结束或失败后 await close；不会关闭宿主全局资源。

代理负责目标 DNS；按上游代理路径的职责划分，保留本地主机名、内部地址与危险 IP 字面量的拒绝规则，不把本机污染的保留 / Teredo 答案当作代理将连接的地址。每次重定向继续校验目的地址，带认证头的请求不能跨源重定向；TLS 验证、响应字节数、超时与跳数限制保留。失败现在保留安全的连接错误码，不输出代理凭据或完整带签名 URL。

## 验证边界

- 真实读取：四个子榜全部成功，413 / 411 / 138 / 159 行；三份 parquet 与数据集元信息均 HTTP 200，全部分数有限。见 `artifacts/leaderboard-diagnostics/2026-10-05-arena-full-read.json`。这一阶段未写热点库。
- 隔离网络回归覆盖：污染 DNS 的代理实际路由、私网地址 / 重定向拒绝、认证头跨源保护、独立取消与连接所有者保留、旧配置补默认与拒绝含密钥地址。
- 正式桌面写入、榜单重算与截图在 `docs/14_Arena网络修复验收.md` 记录，完成前不以单次下载代表交付通过。
