# 显式补编真实新闻历史报告

正式桌面的真实 RSS 首次导入均为 backfill。原实时日报排除 backfill，周报、月报从已保存日报汇编，导致三类报告为空。用户要求继续完成真实数据报告整理，因此增加显式的历史补编命令；阅读和安装仍不触发采集或模型。

历史日报按原始发布时间进入北京时间 08:00 刊期，复用上游七天刊期记忆、一事一条、代表报道、来源配额和正文/快讯排序。读取时重新检查当前 Publication 和来源许可；不修改 backfill、Publication 或热度，不使用不存在的历史信号制造补位。所有历史报告明确标注抓取覆盖不完整，只补编有真实可见材料的刊期。周报、月报只汇编已结束周期里的已保存日报，模型仅编写总述和栏目导读，原事件集合、顺序、防幻觉和长度限制保持不变。

`compileHistory` 使用公开具名 DTO、生成的严格 Remote codec、commandId 幂等与配置 revision 校验。每批最多八期，日报完成后才准入周报和月报，处理中的批次不重复准入。每个任务冻结配置与实际选材；重试沿用冻结材料。付费请求继续经过统一 CallCoordinator 和官方 DSH LLM / 辅助 Session 审计。人工受控重编保留原报告的历史身份。

目标版本的生成器以 `z.object` 表示封闭 DTO，会先剥离未知字段，使 Host 的 strict 校验失去原始输入。构建适配器通过 TypeScript AST 将生成的封闭对象改为 Zod 公开的 `strictObject`，保留官方类型、装饰器元数据、描述符及记录型 JSON。遇到有索引签名的对象交集则停止构建，避免错误收窄开放类型。正式 Gateway 验证额外字段在命令执行前被拒绝。

日报准入等待更早的未完成日报，报告任务串行执行，使七天刊期记忆读取到已经落盘的前期结果；所有报告模型请求仍受共享模型并发限制。实时调度继续排除 backfill；自动周报、月报不读取历史补编日报。现有刊期唯一约束和任务事务沿用，001–014 迁移与 checksum 不改动，用户配置不覆写。历史身份保存在报告的版本化 generator/coverage 内容中，不新增数据库列。

实际验证记录：`artifacts/reports-live/rule-check.json` 使用真实插件库的只读副本、已有真实模型 Publication，确认 16 个历史日报刊期和零新增模型调用。最终正式桌面报告、真实调用审计与原生界面证据另存于同目录；规则副本验证不代表正式桌面完成。
