## SocialData 与 Tibo

凭据卡片提供密码输入、保存／替换／清除、状态、官方获取及计费链接。DSH Credentials 使用插件命名空间；读取不回传密钥，保存成功清空输入。保存凭据不会启动、重试或启用周期工作，更换和清除会使旧任务失效。上游回显的认证值在回执持久化前脱敏。

单次测试由 Host 和存储共同限制：1 页搜索、最多 2 次上下文、最多 5 次模型识别，maxAttempts=1，命令幂等，遵守服务预算与当前租约、epoch 和 generation。不会推进周期游标或处理 backlog。没有重置内容时保留真实“未发现重置”结果，不制造事件。预告与确认仍使用原始监控规则。

**待用户录入 Key 后执行**：临时暂停新闻自动采集并设置本次预算 2/min、3/hour、3/24h，只执行一次测试，核对真实帖子、识别结果、回执和估算／实际费用标记，然后恢复原采集开关与预算。周期 Tibo 继续暂停。失败不自动重试，不充值，不开启自动充值。

当前监控测试任务数 0、SocialData attempts 0。Key 录入请求已给出，未绕过用户亲自录入的步骤。

## 后续修复：官网链接与报告日期卡（2026-10-05）

用户补充要求：在 SocialData 接入卡片增加明确的官方入口，并修复日报、周报、月报右上日期卡频闪。

SocialData 卡片标题旁已新增“SocialData 官网 ↗”，指向经官方首页核实的 `https://socialdata.tools/`，新窗口打开并保留原获取 Key／计费入口。

频闪根因是共用 IssueDots 的画布 effect 依赖每次渲染都重新产生的导航回调，以及刷新后新引用的刊期列表。普通后台更新会重新设置 canvas 尺寸、清空像素并重启 700ms 入场动画。现将资源生命周期限定为报表种类与当前刊期，更新时读取最新的日期格和导航回调，保留已绘制画布；相同尺寸不再重复清空。切换真实刊期、新增历史记录点击和卸载清理继续有效。

`report-canvas-refresh.test.mjs` 的日／周／月三个复现用例在修复前均因画布被重复清空失败；修复后四项用例全通过，包括新刊期可点击与资源释放。全套 28 个文件 / 123 项测试通过，类型检查和构建通过。证据位于 `artifacts/report-flicker-alpha4/`；官网链接是小型展示改动，没有新增镜像实现的测试。

本次安装前暂时暂停新采集／处理任务，等待在途请求自然完成；安装后恢复本次维护前的原设置。原生复验记录随更新包附带，Tibo 的真实付费单次测试仍等待用户自己的 Key，不因本次 UI 修复自动启动。
