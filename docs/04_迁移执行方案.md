# 迁移执行方案与注意事项

## 1. 迁移对象与不迁移对象

本项目是**代码与运行基础设施迁移**，不是作者线上生产数据库迁移。用户不需要备份/恢复功能，因此不包含“导入旧 AIHOT 站点全量数据库”的终端用户产品入口。研发使用的测试数据映射脚本不能当作该功能悄悄发布。

| 原位置 | 目标 | 迁移要求 |
|---|---|---|
| apps/web/app/routes、features | client 内容/管理页面 | 参考信息结构和局部逻辑，不运行原 SSR app；去掉网站 shell 与品牌 |
| apps/api | Host Remote 与受控 ingest | 迁移业务操作与读取语义，删除公开站点服务依赖 |
| apps/worker | Host scheduler/executor | 去进程入口与全局信号；插件初始化/停用可重复执行 |
| backend/sources | core sources + Host 网络/凭据 | 六种类型不删；试抓只预览；快照18项不等于全平台源库 |
| backend/content | core content + repositories | 身份键、输入修订、来源观察与原时间保持一致 |
| backend/editorial | core editorial + LlmPort | 提示词、双评分、结构化与入选规则保留 |
| backend/events | core events + query ports | 14天召回、事实/事件、人工覆盖、热度与趋势保持 |
| backend/reports | core reports + schedule | 日报规则编排、周月报汇编与文字校验保持 |
| backend/publication | read-model + repositories | 统一可见性/许可/撤回，所有UI和讨论素材都走此层 |
| backend/providers | Llm/Embedding/HTTP/Receipt adapters | 分离供应商协议与付费记录；不重复复制 DSH 主模型Key |
| backend/jobs | durable queue + outbox事务 | 替换pg-boss，必须补齐原子入队、幂等与重试合同 |
| backend/leaderboard、monitor | 可选模块 | 算法、种子、采集器、状态机与后台工具完整迁入 |
| industry | 发布快照 + 本地版本化行业配置 | 不自动覆盖用户配置；保留术语、分类、提示词与门槛 |
| database/migrations | 新 SQLite 迁移系列 | 不执行 PostgreSQL SQL；逐字段、约束、查询映射 |
| SelectBench及评测脚本 | core evaluation + admin | 保留gold/预测/模型版本；评测请求预算纳入保护 |
| 原站 about/changelog/feedback | 插件同名功能 | 换成自己的版本、文案与反馈仓库 |
| Docker、部署脚本、sitemap、RSS输出、MCP | 不发布 | 不要求用户运营网站；外部采集输入另有受控适配 |

## 2. M0：先验证四条集成链

### 2.1 拿到真正能构建的上游

取得 upstream.lock.json 的两个提交和相应 DSH 发布包。记录 git rev-parse、Desktop版本、Host实际Node版本、包锁和平台。当前设计阶段的整仓 clone 失败，不要把已有摘要视为全量代码审计。

列出 AIHOT 全部业务文件、SQL调用、process信号、环境变量、文件路径和第三方服务；输出 SOURCE_MAP，要求“原文件 → 目标文件 → 测试 → 差异理由”可追踪。每个源文件必须标记保留/适配/不迁，而不是用目录名代表全部完成。

### 2.2 最小桌面 bundle

用自己的 scope 建立外部 bundle，在干净的官方 Desktop profile 安装。验证左侧一入口、主面板、停用后消失、再次启用恢复、Client热更新及签名资源不被修改。不要用官方仓库 dev:web 能跑来替代桌面包能跑。

### 2.3 存储 / Remote / Worker

数据库 worker加载、node:sqlite、FTS5 trigram、WAL与文件权限探针通过；Host → typed Remote → Client一轮读写可运行；第二个 writer被明确拒绝；随机进程终止后可恢复已提交事务。

### 2.4 模型审计与草稿跳转

不借用已有用户会话运行采集。验证 ctx.llm辅助调用的精确请求Session记录、flush、取消、usage和finish错误。验证 uiWorkspace.startSession预填在有旧草稿/附件的环境中不会覆盖，不发送模型请求。

若任一能力不符合基线，先修 adapter或升级确切兼容基线，并登记ADR。不得使用版本豁免跳过，也不得用虚构API名称写完整实现。

## 3. M1：数据库、队列、回执先行

### PostgreSQL 到 SQLite 的检查表

| PostgreSQL特性 | 迁移处理 |
|---|---|
| timestamptz / now / interval | UTC毫秒字段与明确的时钟port；报告时区由领域算法计算 |
| JSONB操作 / 数组参数 | 保留JSON结构schema；高频筛选字段列化；动态IN参数有上限 |
| ON CONFLICT / UNIQUE | 明确唯一索引与冲突策略，保留幂等语义 |
| bigint / bigint[] | 外部ID用字符串；计数谨慎使用安全整数；不可将精度丢失当无关 |
| advisory lock / SKIP LOCKED | 单写入者 + IMMEDIATE transaction + lease / commandId |
| pg-boss内置调度 | 自有jobs表、活动去重索引、重试时间与恢复逻辑 |
| 同事务业务写+入队 | 同一SQLite连接同一事务；禁止分开两次Remote调用 |
| FULL TEXT / 正则/排序 | FTS候选与明确排序规则重写；以golden fixture比较语义 |
| 数据库触发器 / 级联 | 列出每一条，迁入或显式应用逻辑，禁止静默省略 |

数据库迁移必须有编号与checksum。预期版本不符时拒绝打开写模式。v1不做破坏性降级；升级失败保留旧数据，并关闭自动任务。不设“迁移失败就删库再初始化”的逻辑。

支付回执与任务去重不能被简单Map替代。先写故障注入测试，再移入真实模型与收费采集器。排队状态是持久事实，不是浏览器加载状态。

## 4. M2：逐段移入，不同时改算法

建议顺序：RSS/JSON离线fixtures → 正文提取/去重 → 预筛/双评分的固定响应 → 结构化/写作 → 事件/人工覆盖 → publication → 热度 → 报告 → 其他采集协议与错误路径。

保留来源输入原貌与哈希；对相同输入固定时钟和模型响应后比较上游/插件输出。双评分允许不同真实随机输出，但在固定mock结果下合格判定必须一致。不能只比较“都有标题”而不比较selected/visibility/归属/刊期。

18个快照源的 initialBackfillLimit=8优先于通用30。首次窗口代码按近12×30天处理；未知日期保留原规则，不一律填now。第一次不保存RSSvalidator，第二次普通轮允许补读原列表，是防漏采而非可删除的重复工作。[S04、S05]

所选源删除采用墓碑；保持历史观察和独立参与者身份。文章去重不可误吞同事件的独立来源证据，否则热度会改变。原人工归属覆盖与撤回传播必须测试。

## 5. M3：阅读与管理迁移

逐个原路由/feature建立UI parity条目。清单包含新闻详情、事件详情、公司/方向/内容形态主题和大事记，不能只对照截图导航名称。收藏和已读由本地数据库权威持久，不依赖原站localStorage。

后台试抓、重评和人工纠正保留；但普通“立即采集 / 全站刷新”已被用户删除。按钮语义必须有区别：初始化是真正启动；试抓是预览；单条重评是明确管理操作；页面读取不是采集。

版权/可见性过滤集中在read-model，不在每个页面自行判断。讨论的标题摘要也来自已许可读取结果，不能拿原始被隐藏内容作为预填素材。

## 6. M4：可选模块不是链接占位

模型榜迁移名录、别名、价格种子、冻结尺度、来源读取器、版本化方法和分类展示。价格和排名数据需显示其来源/时间，仓库快照不当作永久真实现价。方法变动同步说明与版本。

Tibo监控保留有效消息识别、状态转换、预告/确认/撤回、重叠抓取与回看补漏、人工修正。禁用后不再轮询，任务在关闭→开启循环中只能注册一次；旧历史保留。

## 7. 停用、清空、升级的不同含义

停用：移除入口、停止timer、关闭服务与worker，保留所有数据。
卸载：删除代码依赖/组合选择，不删除专属数据目录。
清空：二次确认；先持久设置deleting状态并改变runtimeEpoch，停止外部调用；迟到响应必须带epoch校验；删除仅本插件数据；回到未初始化。共享DSH凭据与聊天不动。
升级：验证peer → 关停 → schema迁移 → 健康检查 → 恢复调度。升级不能重新seed被用户删除的默认源。安装事务失败和业务schema失败分别显示，不能吞并成一次“更新完成”。

## 8. 发布前的资产与许可

保留MIT原文及来源映射；默认源内容仍属于发布者。自己的插件品牌、图标、关于页与反馈地址独立。不要带原Logo、任何源PDF、用户聊天、密钥、线上数据、完整字体文件、buildcache或node_modules。

用打包后的npm产物做安装测试。检查动态Client、worker、生成Remote、prompts路径；仓库里存在文件不代表它已打进发布物。

## 9. 禁止的捷径

不因SQLite改造工作量大而要求用户装PostgreSQL；不把所有表序列化成一份JSON；不绕过ctx.llm；不通过Agent聊天定时拉取；不删双评分/事件；不把“本地定时”宣传成退出后在线；不以备份/恢复入口替代迁移正确性；不把本规格包改名成已完成插件。
