# 验收与发布门禁

以下是可执行验收规格，不是测试通过记录。所有状态初始为 `not-run`。

## 1. 环境与方法

使用锁定源码提交、干净 DSH Home、固定时钟、mock 网络/LLM 和本机 SQLite 组合；随后在真实官方 Desktop 安装产物上执行平台测试。真实付费服务只在显式授权和小预算下冒烟，不能让 CI 默认调用收费 API。

单测覆盖规则与解析；集成测试覆盖事务、回执与恢复；golden测试对照原项目固定输入；客户端测试覆盖所有已确认页面；桌面测试必须用实际打包运行时。不得将 mock 通过写成真实服务验证。

## 3. 故障注入位置

在请求预留后、发送前、发送后无响应、收到响应未落盘、raw response落盘后、业务事务开始后、业务提交后响应丢失、迁移中、关闭中、清空中分别终止。记录DB、回执、attempt、source cursor、publication与任务状态。目标是状态自洽和受控恢复，不是“每条都自动重跑”。

## 4. 性能基准

记录硬件、Host Node/SQLite版本、数据量、正文大小、索引、查询样本与暖/冷缓存。至少包含10万摘要、2万事件关系、历史报告和收藏；本地读取p95目标500ms，属于工程目标而非已测数据。长文本搜索和中文1–2字词单独统计。模型延迟不得混入本地查询指标。

## 5. 发布阻断

所有INIT、CHAT、COST、DATA、SEC和PACK案例通过；完整首版功能已验收；可选模块已实现并测禁用路径。源映射无未解释缺项；新增SQL和Remote经过审阅；许可证/NOTICE齐全；发布物不含用户源PDF和秘密。性能有实际报告，无明显聊天阻塞。

## 6. 记录格式

每次执行写测试版本、环境、上游SHA、前提、操作、实际结果、日志/截图路径、是否通过、缺陷号。用例状态只能在真实执行后从not-run转pass/fail。specs本地一致性检查只验证资料结构，不更新这些状态。
