# 技术架构与选型

版本 v1.0 · 2026-10-03 · 本文所有“应 / 采用 / 必须”是实施规格，不是已经实现的结果。

## 1. 定案与原因

采用 **DSH 外部 Cordis 组合包 + DSH 原生 Client + Host 业务服务 + 插件关系存储 Provider + SQLite 持久队列**。用户安装一个组合包；拆包是实现边界，不要求用户逐个安装组件。

保留 AIHOT 的采集、编辑、归组、热度、报告、模型榜、监控和校准算法，替换网站运行基础设施。既不把完整网站 iframe 嵌入，也不让 Agent 每隔一段时间“自行搜索新闻”。

### 技术选择表

| 领域 | 定案 | 不采用 | 决策依据 |
|---|---|---|---|
| 开发语言 | TypeScript / ESM，严格类型 | 另加 Python 业务后端 | 两边主要业务均为 TS；减少跨语言状态协议 |
| 包管理 | pnpm workspace；落地以锁定 DSH 基线工具版本创建锁文件 | 依赖 latest、直接带 node_modules | 可重现构建、可检查发布视图 |
| 构建 | tsdown，按 DSH Client 外部模块规则生成浏览器产物 | 另一个独立 Vite 站点常驻 | 同一 React / Cordis 身份；遵守 dsh.client [S16、S19] |
| UI | DSH 共享 React 18、Slots、UI primitives、框架 store | 整个 apps/web 直接运行；Zustand 替代框架约定 | 框架提供既有扩展面和主题；不复制 shell |
| 持久化 | 自有 HotstreamStore 服务；node:sqlite；单个专属 DB | PostgreSQL、把正文全塞进 storageDomain | 原库需要关系约束、索引、跨表事务和迁移 [S09、S10] |
| 数据库执行 | node:worker_threads 单写入工作线程；typed repositories；预处理 SQL | 在 Host 大量同步扫描；通用 ORM 自动翻译 | 隔离同步数据库负担，SQL 语义显式可审 |
| 调度 | Host 生命周期内计时 + SQLite 持久业务队列 | pg-boss；以会话 Schedule 驱动 Agent | 不依赖会话，业务与任务能一起提交 [S08、S11] |
| 模型 | DSH ctx.llm 的 Host 适配器；Zod 输出校验 | 每条内容开完整 Agent；重复持有主模型 Key | 复用已配置路线，保留请求可审计 [S13、S14] |
| 向量 | 默认原词面路径；可选 embedding Provider | 强制另装向量库；将聊天模型当 embedding 模型 | 原召回允许无 embedding；维度与版本必须隔离 [S21] |
| 检索 | SQLite FTS5 trigram + 有界短词查询；Repository 隔离 | 扫全库 JSON、沿用 Postgres 全文 SQL 不改 | 适应中英文子串；精确排序差异需回归 |
| Host/Client | DSH 已认证 Remote / Typert 扩展 | 自建公开网站 Fastify、直接暴露 SQL | 单一 Host 权限与消息协议 |
| 测试 | Vitest、Testing Library、Playwright；SQLite 故障注入 | 仅接口 mock 即称桌面兼容 | 必须测试已打包桌面程序和实际存储 |

具体 devDependency 版本由冻结基线的 manifest/lockfile 提取。已核对 Desktop manifest 为 0.2.1-alpha.1，含 TypeScript ^6.0.3、pnpm 11.7.0、React ^18.2.0；不是要求再打包这些运行时。Cordis 与 DSH 服务必须走匹配的 peer/dev 关系，不能把另一份核心内联进去。[S18、S19]

## 2. 为什么不直接使用原讨论中的 ctx.storage

DSH `storageDomain` 是 schema 校验的 KV 数据形式。官方文档明确：没有跨表事务、二级索引与通用数据迁移；打开时加载记录到内存。[S09] 这不适合把长期保存的全量新闻、事件图谱、任务账本作为一个大领域常驻。

SQLite backend 的存在不代表其公开 API 暴露任意 SQL。不得通过反射获取其私有连接，或自行修改宿主数据库内部表。[S10]

因此新增 **插件自己的关系存储能力**：

```text
core / host / optional modules
            ↓ Repository / Transaction ports
HotstreamStore（本插件定义的服务，不是声称已有官方 API）
            ↓ typed worker messages
SQLite Provider（插件所有者）
            ↓
$DSH_HOME/data/hotstream/hotstream.sqlite
```

按照“接口 / 实现 / 消费者”的插件边界组织。SQL、连接、事务、迁移和文件权限只属于 provider；业务层和 Client 均不触碰介质。基础设施提供方和消费方使用不同的 service key，并通过 inject 管理依赖。可复用官方文件权限与关停做法，但不能引用私有未导出的 helper。

DSH Storage 仍由宿主自己使用；本插件不改全局默认 backend。插件的配置与业务数据放在同一专属库，减少跨介质提交。凭据仍由 DSH 管理，库中只存引用。

## 3. 运行组件

```text
DSH Desktop / Host
 ├ Hotstream Host
 │   ├ 初始化与功能开关
 │   ├ 持久调度器 / 执行器
 │   ├ 原采集、正文与编辑流水线
 │   ├ DSH LLM + Credentials 适配
 │   ├ 公开读取语义的本地查询服务
 │   └ Remote 注册、错误归一化、生命周期
 ├ Hotstream SQLite Provider
 │   └ 独占 DB worker：关系查询、事务、回执、作业、迁移
 └ DSH Client
     ├ 左侧一个热点入口
     ├ 内容、报告、主题、收藏与可选模块
     ├ 设置 → 独立后台管理空间
     └ uiWorkspace 新会话草稿预填
```

Host 只编排异步工作，不执行大规模同步 SQL。数据库 worker 只接受已声明的 repository 命令，不提供 arbitrary SQL Remote。模型调用留在 Host，通过 `ctx.llm` 进入现有适配器。CPU 重的相似度比较分块让出执行权，超过性能预算后再迁入独立计算 worker；归组仍保持单执行者，不能用“并发越大越快”改变归组语义。

worker 与 Host 同生共死，不是守护进程。目录中保存 worker 入口为明确发布产物；从 `import.meta.url` 解析，不依赖源码路径或 process.cwd()。

## 4. 关键数据实体与所有权

| 实体 | 所有者 | 核心合同 |
|---|---|---|
| Source | source 模块 | 配置版本、enabled 与 blocked 分开、游标、上次成功、下次运行、删除墓碑 |
| Article / Observation | content 模块 | 统一身份键、输入修订；多来源观察不能因文章去重一起消失 |
| Analysis | editorial 模块 | 输入修订、独立评分槽位、模型路由、提示词与行业版本、结构化结果 |
| Fact / Story / Membership | events 模块 | 区分同次发生和后续；人工标记优先，归组版本可追溯 |
| Signals / HotRanking | events 模块 | 独立参与者、原事件时间、数据覆盖与规则版本 |
| Publication | read-model 模块 | 对外可见性唯一权威；状态、标题摘要、精选与来源资格 |
| Report | reports 模块 | 唯一刊期、固定时区、条目快照、正文/快讯与模型导读分开 |
| Bookmark / ReadState | library 模块 | 全局本机用户状态、必要显示快照；不跟 workspaceId 绑定 |
| Job / Attempt | runtime 模块 | 稳定 dedupeKey、输入/配置版本、租约、有限重试、可恢复状态 |
| Receipt / Budget | cost 模块 | 请求已发送与结果未知分开；原始响应先持久再使用 |
| IndustryVersion | industry 模块 | 分类、实体、门槛、提示词版本；不能由任意 JavaScript 驱动 |
| Optional Records | 各可选模块 | 模型名录/尺度/快照和监控状态/待审记录，不共用模糊状态字段 |

`specs/storage.reference.sql` 是关系约束设计草案，覆盖核心原子性测试，不是完整 AIHOT schema 转换。执行 M2 前必须完成原字段逐项映射，尤其 publications、评测、模型榜及监控表。不得用一个 JSON 字段的存在宣称所有查询与功能已迁完。

## 5. 持久任务队列，不承诺外部恰好一次

### 作业身份

源采集按 `(sourceId, scheduledSlot)` 生成触发身份；同一个源只允许一项活动 fetch，错过多个 slot 合成一项恢复任务。分析按 `(articleId,inputRevision,stage,configVersion)`，评分额外区分 `scoreIndex`。刊期按 `(kind,periodKey,timeZone)`；归组按文章修订，执行串行。

作业状态：`queued → running → succeeded`；失败走 `retry_wait / blocked / failed`；取消走 `cancelled`。任务 lease 只防止本地重复执行；不能证明远端没有收费。

### 原子提交

在同一个 SQLite transaction 内完成：文章更新、版本更新、下一个 stage 的作业插入、采集 cursor / 下一时点更新。原始外部请求在事务外发起；事务中不等待网络。worker 消息丢失后用稳定 commandId 查询已提交结果，不能直接当失败重跑副作用。

独立事务例子：

```text
BEGIN IMMEDIATE
  核对 source/config/input revision
  upsert 文章和来源观察
  INSERT 下一步 job（活动 dedupeKey 唯一）
  更新成功 cursor / source clocks
COMMIT
```

回执收到后：先存 raw response 和状态 `received`；业务写入事务读取其响应、更新 analysis/publication、入下一步任务、标记完成。程序中断在这两次持久化之间时恢复业务，不重新调用模型。

### 请求身份

logicalKey 至少包含 service、stage、主体及其输入修订、精确 provider/model、prompt hash、行业/配置版本、输入 hash、slot（尤其 score:1 与 score:2）、显式重跑标识。不能只用 articleId；不能把两次独立评分缓存成同一次。

### 失败分类

* 尚未发送 / 明确拒绝：按有限策略重试，不占“未知结果”特权。
* 已返回有效 raw response：永远先尝试复用。
* 发送后超时、进程终止、响应持久化不确定：`unknown`，预算已计一次；不立即重发。
* 保留上游最多一次受控释放的思路：30 分钟后仍无响应证据、预算允许且租约已释放，可追加一次重试；再次未知转人工确认。具体供应商有幂等 token 时额外利用，不作通用保证。[S08]

人工“确认重试”必须显示可能重复收费，生成新的 attempt，仍受预算限制。禁止下层 HTTP、模型适配器、队列各自再套隐形三次重试。

## 6. 模型与 DSH 接口

使用 `ctx.llm.listProviders/listModels` 可见目录作配置来源，以 `{provider,model}` 引用路由。初始化默认值可以来自 DSH 当前默认模型，但确认后保存为固定选择。更换主聊天模型不会改变热点任务。

结构化结果通过 Zod 校验；未支持原生 JSON schema 的 route 可采用明确 JSON 文本合同，不假设全体供应商都支持同一参数。模型结果包含工具调用时拒绝，绝不执行。双评分每次为全新请求，没有第一分传给第二分。

### 请求日志是硬合同

官方要求模型可见输入可由会话日志重建；`ctx.llm` 不会替任意调用者自动完成日志。[S13] 官方标题生成器是可参考的辅助调用：先追加精确请求事件，再发流，不需要 agent-loop。[S14]

本插件需实现 `AuxiliaryLlmAuditPort`：将精确不可变 messages、route、prompt/config hash 与结果记录为专属持久 Session 事件。专属审计日志与 ordinary user chat 分离，通过后台调用记录查看；不虚构 `hiddenSession=true` 参数，也不冒用 subagent 身份隐藏会话。

在 M0 验证官方 Session/Persistence 能否在插件命名空间正确建立这种仅审计、不激活 Agent 的记录与生命周期。日志 flush 成功才发起模型请求。原子预算回执与会话审计通过稳定 requestId 联结；审计写失败不调用模型，收到响应后的结果审计失败只重写审计，不能再发模型。

如果此适配尚未验证，阻断真实模型执行和发布；不能悄悄改成直接抓 DSH Key 调第三方 SDK，也不能把普通日志冒充官方 Session 记录。

### Embedding

单独声明可选 embedding port。默认关闭并走原词面召回；用户选向量模式后才使用明确支持 embedding 的 Provider 和凭据引用。未证实 DSH 提供的统一 embedding 接口不得自行编造。向量表按 model、dimension、textHash 隔离；更新路由需重建对应向量，不混算。

## 7. 调度与恢复

默认每次从库读取最近到期项并设置下一次 Host timer；不为所有文章创建一个操作系统 timer。重启/恢复时扫描到期 source、未完成 job 与尚有数据支持的缺失刊期，限制每轮入队规模。源触发合并，历史处理进度不丢。

源 interval 保持独立。固定间隔使用持久 UTC 时点；报告使用原 Asia/Shanghai 刊期。系统时钟回拨时重新核对 due；跨时区旅行不重置新闻窗口。

两类补跑分开：错过十次采集只补一轮；日报有多个不同缺失刊期时按原报告编排补足有证据的刊期，但限制并发，绝不从没有收集过的数据编出历史报告。可以在后台看到补生成进度。

关停顺序：关闭准入 → 撤销 timer/订阅 → 取消未发请求 → 给已收到响应的持久化短暂完成窗口 → 未决标 unknown / 中断 → flush DB → 停 worker → 注销服务。不得调用 process.exit、处理宿主全局 SIGINT 后直接退出、复用一次已 abort 的全局 AbortController。

## 8. Client、Remote 与讨论入口

Client 通过 DSH slots 注册一个全局主面板和内部导航。组件不持有 ctx；共享状态经官方框架 hook/store，持久业务数据由 Host 权威返回。详见 [S16]；不能把任意第三方状态管理范式硬接进去。

Remote 的方法名、DTO 和错误码由本插件声明，例如 `hotstream.library.list`、`sources.update`、`runtime.status`、`initialize`。这些是设计名称，不是声称官方已有 API。用冻结版本的 Typert 生成工具验证外部包加载、导出与权限，前端不允许执行任意 SQL 或传入脚本。

讨论走 `uiWorkspace.startSession` 的公开 prompt 路径；该服务可能复用空白会话，需检查不覆盖旧 draft/attachments。如果不能满足“新上下文 + 保留现有草稿”，适配其受支持的新会话流程，而不是操作 DOM 或直接调发送接口。[S15]

## 9. External 输入保留方式

核心 ingest 是 typed Host service，其他受信插件可接入。为外部脚本提供一个**默认关闭、仅配置 external 类型后明确开启的本机接收适配器**。优先复用 DSH 可公开授权的服务器扩展；若官方 Desktop 私有鉴权无法给外部脚本安全使用，则由同一 Host 管理 loopback listener，不另开常驻进程、不开放公网。

接收通道绑定 127.0.0.1，随机端口、独立高熵 token、严格 Host/Origin、禁 CORS；默认请求 ≤2 MiB、批次 ≤100 条，token 由凭据服务持有。浏览器来源请求拒绝；token 不写查询串。路径与发现方法在 M0 按具体 Host 能力确定，文档不捏造官方 ingest 端点。

打开此通道前必须已有初始化同意与 external 源。传入内容遵守相同去重、预算与模型路径。原站公开 Agent API/RSS/MCP 仍不迁移；本机 ingest 不是一个给 Agent 查询新闻的接口。

## 10. 性能、升级与发布

采用 SQLite WAL + foreign_keys + busy_timeout；实际 journal 模式与文件系统能力探针验证。一个 writer；长事务禁止网络；分页查询限量。全文 FTS5 trigram 索引可重建，1–2 字词使用限制范围的 LIKE 并转义；不假定 Postgres 与 SQLite 排序完全相同。

启动迁移在加载调度器之前，事务与校验成功才开放写入。支持的 schema 范围之外只读/拒绝，不重建空库覆盖；错误与升级说明清晰显示。常规迁移只增量/可事务恢复，首版不以导出备份按钮替代数据保护；不做破坏性降级。

所有版本兼容是实测门禁。第三方编译包不会复制仓库专属 `workspace:*`、`private:true`、内部相对 tsconfig 路径去 npm。对外包名使用自己的 scope，构建产物包含 worker、Client、行业资源、生成 Remote、许可证；不包含密钥、会话记录、源 PDF、原站品牌或字体文件。
