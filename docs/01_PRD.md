## 产品目标与非目标

### 产品目标

普通 DSH 用户安装一个组合包，即可在桌面内浏览已加工的行业资讯，管理自己的信源，并自动得到精选、事件热点与报告。默认提供 AI 行业配置，允许用户调整到其他行业。无需另外安装数据库、Docker 或服务器。

| 用户 | 核心任务 |
| --- | --- |
| 普通阅读者 | 默认配置初始化后，打开即读；不需要写爬虫或维护数据库。 |
| 关注特定行业的用户 | 启停信源、修改分类和筛选标准，形成自己的一套热点库。 |
| 高级用户 / 开源贡献者 | 新增适配源、校准模型、排查失败；保留原流水线的来源追溯和人工修正。 |

### 成功标准

安装与初始化有明确反馈；无需手动采集；重复启动不重复导入；窗口隐藏后照常采集；退出后不伪装在线；故障不拖垮其他信源；收藏、报告、配置跨重启保留；用户点击讨论按钮时不自动花费模型额度。

### 明确不做

不做自媒体选题库、账号个性化打分或稿件工作流；不提供 Agent 主动查询热点的工具；不迁移公开 Agent 接入页、公开 MCP/RSS/API 输出与网站 SEO；不做云同步、备份/恢复、上游信源同步按钮。

不引入独立常驻系统服务；不承诺 DSH 彻底退出、电脑休眠或关机后继续采集；不按工作区复制数据；不提供首页「立即采集 / 全量刷新」按钮；不直接搬入原站品牌与运营数据。

功能范围是完整新闻能力的原生迁移。下面的实施阶段仅用于分批验收，不把尚未迁入的保留功能悄悄移出首版。

关于页展示上游来源、许可说明和当前插件版本。反馈跳转本插件 Issue 模板；打开前用户确认，默认不附带日志、正文或凭据。


## 信息架构与页面导航

```text
DSH 左侧：热点
  ├ 精选（默认首页） / 全部动态 / 热点榜
  ├ 报告：日报 / 周报 / 月报
  ├ 主题 / 收藏
  ├ 模型榜 / Tibo 监控（开启后显示）
  ├ 关于 / 更新日志 / 反馈
  └ 设置
      ├ 常规 / 模型 / 功能模块 / 采集与预算 / 数据
      └ 后台管理 → 独立二级空间
```

后台管理包含：仪表盘、信源管理、内容管理、事件修正、精选评测、任务运行记录、模型/付费调用记录和高级配置。返回内容区时恢复原筛选、阅读位置，不新建采集任务。

### 布局原则

只向 DSH 主侧栏增加一个入口；其余导航属于插件内部。沿用 AIHOT 的内容组织方式，使用 DSH 的主题、字体、间距、图标与通用控件；不嵌入 iframe，不独立加载另一份 React。设置与后台不混进新闻列表。[S16、S19]

### 状态展示

内容页顶部显示上次成功采集时间、当前处理状态、待处理数量、异常源数量；信息不足时明确“尚未初始化 / 尚未产生精选 / 暂无报告 / 数据可能过时”。刷新页面只读已有结果，不触发模型。

列表保留来源、原发布时间、摘要和必要标签；文章详情提供原文、译文或可许可正文。切页与搜索通过分页请求更新；首版不加载整个历史库到浏览器。


## 首次安装与显式初始化

> 只有用户点击「初始化」并通过必要配置检查，才导入数据、创建采集任务和调用外部服务。安装或打开未初始化页面本身不访问新闻源、不试调用模型。[已确认]

| 阶段 | 行为与结果 |
| --- | --- |
| 未初始化 | 展示内置信源数量、处理模型选择、费用提示；允许查看默认配置。 |
| 检查配置 | 解析 DSH 已有模型，选定固定 provider/model；检查本地可写与数据库能力，不发送付费探测。 |
| 创建本地库 | 先执行 schema 迁移和唯一锁，再原子导入快照、记录初始化版本。 |
| 导入信源 | 18 项全部默认启用；不重复覆盖用户已存在的配置；缺凭据与无效配置单独标记。 |
| 首轮运行 | 各信源按原首次规则进入队列；结果逐步可见，不等全部完成才可阅读。 |
| 自动调度 | 初始任务与后续间隔共同持久化；同一源串行，初始轮未完成不重复入队。 |

结构初始化成功不等于 18 个来源全部联网成功。部分失败显示“已初始化，部分来源待恢复”；记录失败原因并按策略重试，不让一个失效链接阻塞全插件。

初始化按钮使用单次请求身份和互斥锁。重复点击、重启中断或客户端超时后重试必须接续已有状态，不能清空库重来。数据库失败时不发出外部请求。

已经初始化的用户重装插件后直接读取旧数据并恢复到期任务，不重新导入快照。用户主动清空数据后才回到首次状态。[S01 第36–38页；S02]


## 默认信源与首轮回填

### 默认策略已锁定

内置迁移时公开 sources.json 的一份快照；全部默认启用。之后由安装者新增、删除、启停和修改，插件更新不重新补回用户删掉的源，不自动同步上游。[S01 第36页；S02]

> 实际基线是 18 个 RSS 示范信源，不是作者线上完整信源库；这 18 项分别配置首次最多 8 条。不得把历史讨论里的“800+”或通用“30 条”写成默认交付数量。[S03–S05]

| 项目 | 保留规则 |
| --- | --- |
| 采集间隔 | 逐源保留快照里的 60 / 120 / 180 分钟，用户可编辑；不统一成每小时全抓。 |
| 通用首次规则 | 未覆盖时最多 30 条；代码的 12 个月窗口按 12×30 天计算；来源覆盖优先。 |
| 本包首次上限 | 18 源每源 8 条，理论首轮最多 144 个候选；实际取决于源返回、去重和过滤，不是付费请求次数。 |
| 回填时间 | 沿用原 publishedAt / backfill 语义；不把历史内容伪装为今日新增或制造热度。 |
| RSS 游标 | 首次回填不保存整份 feed 的 validator；普通轮成功入库后再保存 ETag / Last-Modified。 |
| 失败 / 304 | 失败不推进成功游标；304 视为正常无更新，不生成新的模型任务。 |

新增源也走原类型的首次逻辑。公众号有自己的任务路径，external 被动接收，不把通用 RSS 首轮规则硬套到全部类型。

原有自适应采集策略如在基线启用，应按原配置边界迁移，并展示“配置间隔 / 实际下次运行”；用户锁定间隔时以显式配置为准，不通过升级偷偷调频。


## 信源管理与跨行业配置

| 类型 | 用户配置与限制 |
| --- | --- |
| RSS / Atom | 名称、feed URL、级别、间隔；保留类别过滤与全文字段。 |
| 网页列表 | 列表地址、CSS 选择器、详情规则；普通解析不执行 JavaScript。 |
| JSON 接口 | 地址、条目路径、字段映射；认证信息单独存凭据，不放普通 JSON。 |
| X 账号 | 查询或账号、SocialData 凭据；合并采集与分页游标沿用原规则。 |
| 微信公众号 | 账号标识、Dajiala 凭据；按原专用任务执行。 |
| External | 受控外部输入；仅主动开启的本机接收通道，鉴权、限量、校验后入流水线。 |

管理操作：新增、编辑、启停、删除、查看健康状态与失败原因。删除源默认停用并保留历史关联（逻辑删除），不级联删文章或收藏。缺凭据：enabled 仍反映用户选择，运行状态为 blocked，而不是自动改成停用。

保留后台“试抓预览”，它是配置诊断，不是被删除的首页手动采集按钮。仅初始化后可用；不写新闻库、不触发评分。可能使用付费采集时明确提示并计入同一预算。[S07]

### 跨行业

源、分类/主题/实体、预筛提示词、评分标准、门槛、术语和报告栏目作为版本化行业配置管理。第一版内置一个 AI 配置，不预置行业市场、不做多行业多库。更换行业需明确修改筛选标准，不只是换链接。

配置变更只影响新任务，旧文章保留当时行业与提示词版本；后台可显式重评选定内容，先估计任务规模并确认费用。禁止从配置中执行任意脚本。


## 内容处理与精选规则

```text
收集 → 身份去重与版本 → 正文提取 → 预筛
                    ├ 评分 1 + 评分 2
                    └ 结构化事实 / 分类 / 标签
                         ↓
                     标题与摘要
                         ↓
              事件归组 / 新信息判断
                         ↓
          精选与全部动态的统一读取投影
```

以原项目为业务基线，不用 Agent 自由规划代替确定性流水线。每一步有持久任务状态、输入修订、提示词版本、模型路由和结果校验。[S05、S06]

| 规则 | 验收要求 |
| --- | --- |
| 预筛 | 只有明确 BLOCK 阻断；UNKNOWN 继续。材料不足时不能凭空打明确负判。 |
| 独立双评分 | 每次请求不包含另一分数；回执键必须区分 score:1 / score:2，不能被缓存合成一次。 |
| 入选门槛 | 保留 T1=60、T1_5=65、T2=76；两次和 ≥ 2×门槛仅代表够分，还要完成归组与新信息判断。 |
| 结构化与写作 | 保留分类、实体、事实、标题身份约束；高价值与普通条目采用原对应写作路径。 |
| 发布状态 | 模型报错、格式错误、归组未完成不自动放行精选；超过等待阈值在后台告警。 |

文章原文、摘要、翻译与媒体都经过同一权限/可见性读取层。页面不得为“更快显示”直接读未经发布判断的原始表；原文抓取许可和站内展示许可分开。

不得为保证完成率改成单次评分、删除事件判断或让失败内容混入精选。这属于业务改变，须单独决策。


## 事件归组与热点榜

数据层保留 Article → Fact → Story 以及参与信号；不同来源报道同一次发生可以归入同一 Fact，后续进展关联同一 Story；不能因为同公司或相似标题就合并。[S21]

| 环节 | 保留行为 |
| --- | --- |
| 召回 | 近 14 天候选，已配置 embedding 时使用向量；未配置时使用原词面相似度路径。 |
| 关系判定 | 保留同次发生、同事件后续、无关、综合稿区别；模糊结果按原校验规则处理。 |
| 人工修正 | 支持归组调整、拆分/合并、独立展示；自动任务不得覆盖人工归属。 |
| 热度 | 48 小时窗口；按独立参与者计数；贡献按 24 小时半衰衰减；同源重复不累加。 |
| 趋势 | 与 6 小时前比较；采集落后或新加来源导致不可比时保留 unknown，不伪造涨幅。 |

```text
基础热度 H = Σ 2^(-Δ小时 / 24)
求和对象：当前 48 小时内去重后的参与者；
每个参与者取其最新有效证据，页面倍率沿用原规则。
```

热点详情展示综述、最新进展、原始报道、来源与时间线；允许时间线正序/倒序。热点指标表示监测范围内的关注程度，不声称全网真实热度。

更改信源所属实体、下架内容、人工归组后，重新生成受影响的投影和热度，不删原始审计。embedding 配置改变必须隔离模型/维度与文本哈希缓存，不能混算旧向量。

UI 加载只读取持久结果；模型归组采用串行执行，避免并发创建重复事件。


## 日报、周报与月报

> 原项目当前日报不是“再让模型写一篇日报”：它按既有精选与事件规则编排；周报、月报由日报汇编，模型只负责总述和部分栏目导读。[S06]

| 刊期 | 首版默认与边界 |
| --- | --- |
| 日报 | Asia/Shanghai 每日 08:00；窗口前一天 08:00 至当天 08:00；按原去重、跟进、来源配额编排。 |
| 周报 | 周一 10:00；从对应周的日报汇编；同一事件跨天归并，保留原限额与排序。 |
| 月报 | 每月 1 日 10:30；从对应月的日报汇编；保留原总述防幻觉规则。 |
| 归档 | 按刊期唯一键保存；已有一期不因页面打开重新生成。 |
| 错过刊期 | 恢复后检查有数据支撑的缺失刊期并有界补生成；不同于重复执行每次错过的采集计时。 |

日报编排保留一事一条、最近刊期去重、直接新动作或多方报道的跟进规则、正文/快讯分层和来源配额。不得重新用一个总分替代原编排。[S06]

周/月报模型生成的文字不得增删事件。校验到未被材料支持的名称或数字时采用原模板回退，而不是重试无限生成“满意文案”。缺少刊期数据要显示覆盖不足，不编造缺失日报。

源发布时间与刊期时间存 UTC；刊期按原 Asia/Shanghai 解释，UI 显示明确时区。首版不跟随系统旅行时区改变刊期边界。[S22]

没有合格内容时保留空状态和告警，不生成充数报告。阅读报告不触发付费调用；对事件和文章的撤回必须同时反映到报告读取层。


## 阅读、主题与收藏

| 功能 | 用户行为与数据要求 |
| --- | --- |
| 文章阅读 | 中文标题摘要、原文链接、原时间、来源、标签；按许可显示正文、翻译与媒体。 |
| 主题 | 公司 / 方向 / 内容形态；保留实体、标签关系与上游大事记，不能压缩成普通标签列表。 |
| 搜索 | 支持标题摘要与全文相关查找；分页、排序、加载失败和无结果分别显示。 |
| 收藏 | 添加 / 取消，列表保留所需快照及引用；源被删除后收藏仍可定位。 |
| 已读与偏好 | 同一热点库内统一保存，切换 DSH 工作区仍保留，不靠单个窗口 localStorage 作为唯一权威。 |

全部动态并不包含所有原始抓取垃圾。仍按原预筛、可见性、处理进度和撤回规则输出。原文不足的条目显示具体状态，不用虚构摘要占位。

窗口或页面重新挂载后恢复最近浏览位置与筛选。长期正文不全部传给 Client；单条详情按需读取，大列表虚拟化或分页。

用户收藏与已读状态从原网站的浏览器本地机制迁为插件本地持久化。这是存储适配，不增加账号注册、跨设备同步或账户云服务。

不迁移原收藏页的导入/导出能力：用户已明确不要备份/恢复。数据仍按已确认保留规则保存。

本机“收藏的内容”与可展示的“被撤回正文”要区别：保留收藏标识和撤回说明，内容读取不得绕过撤回或许可。


## 可选模块与附属页面

### 模型榜

首版保留上游评测采集器、模型名录/别名、冻结尺度、排名计算、分类榜、来源页、方法页与必要价格种子。不是只有一个空页面。关闭后不再采集或计算，重新开启复用已有快照。[S20]

评测来源失败时沿用最后成功快照并显示更新时间；有可选 Key 的来源缺 Key 不冒充完整覆盖。参数与方法说明必须和实际算法版本一致，不展示示例值当真实成绩。

### Tibo / Codex 重置监控

保留消息识别、状态机、历史、预计时间与原帖链接；SocialData 凭据及监控模型由设置提供。关闭后取消后续任务，已处理历史仍保留。缺凭据时显示待配置而非静默空白。[S20]

模型只识别材料，状态转换沿用上游规则。预告不能被当作已完成重置；待人工确认的记录留在后台。仅说明模块能力，不承诺任何账号额度或供应商行为。

### 默认与行业适配

两个模块作为首版实现默认关闭；开启时显示依赖和可能费用。它们关闭不影响新闻链路；切换到其他行业时可继续关闭，不强制出现 AI 专属菜单。此默认值属于技术/产品落地定案。

### 关于、日志与反馈

关于页保留上游 attribution 与许可证；更新日志展示本插件的变动；反馈跳转本插件仓库。外部通知推送不是首版必需功能，不自动把热点或日志发到第三方群。


## 「和 AI 讨论」交互

> 点击后进入新的 DSH 对话上下文，预填标题、摘要、原文链接；不自动发送，不调用 Agent 工具，不改动当前已有对话。[已确认]

```text
以下是我选择的热点材料，供接下来讨论：
标题：{title}
摘要：{summary}
来源：{source}
发布时间：{publishedAtWithTimezone}
原文：{originalUrl}

我想讨论：
```

具体入口位于文章/事件详情和列表条目操作中；单次处理一个条目，防重复点击。事件可以附有限个原报道链接，默认最多 5 个；材料总长度上限 12,000 字符，超出时明确截断，不静默丢失出处。此上限为技术默认。

官方 uiWorkspace.startSession 已有 prompt 参数，可走 DSH 的新会话流程。其实现可能复用合格空白会话；“新对话”不意味着可清空任意现有草稿。不得默认 clearPreviousDraft=true，更不得直接写 DOM。[S15]

有旧文字、附件或发送阻塞的目标不能覆盖；需要创建真正干净的会话或提示选择。没有可用工作区时走官方选择流程，不自动为插件创建用户目录。

跳转失败或被之后导航取代：保留热点页面与素材，不创建重复草稿，不自动改走发送接口。正常新会话的模型由 DSH 决定，与后台热点处理模型独立。

原文和摘要是不可信材料：只能作为待讨论引用，不能提升为系统指令。公开链接中若包含密钥、签名凭证等不得带入草稿。


## 设置与后台管理

| 设置区域 | 内容 |
| --- | --- |
| 常规 | 语言跟随 DSH、主题跟随 DSH、行业显示名、状态说明。 |
| 模型 | 固定处理模型、分步骤覆盖、可选 embedding；跳转 DSH 模型/凭据设置。 |
| 功能模块 | 模型榜、Tibo 监控开关和配置诊断。 |
| 采集与预算 | 自动采集总开关、并发与调用上限、逐源间隔的管理入口。 |
| 数据 | 空间占用、普通日志/缓存保留期、清空数据（二次确认）。 |
| 后台管理 | 仪表盘、信源、内容、事件、精选评测、任务与调用记录。 |

后台操作沿用原诊断与校准能力，包括查看阶段状态、受控重评、事件归属修正、待确认监控记录处理。重评/重新归组不是全站采集按钮；必须显示影响范围，可能增加费用的操作须确认且受同一预算限制。

高级设置可以编辑行业规则、提示词、阈值和模型覆盖；保存先做 schema 校验，失败保留草稿。多页面并发修改用版本号 compare-and-set，拒绝覆盖较新配置。

前端只拿凭据已配置状态与掩码，不读回完整 Key。对已有 DSH 模型只保存路由引用，不复制其秘密到插件库。新增第三方服务凭据走受控凭据接口。

本机插件不复制网站的管理员登录/默认密码系统。边界是 DSH 已认证 Host 与安装插件的权限；前端隐藏按钮不能替代 Host 端参数、权限和状态验证。


## 自动采集与生命周期

| 状态 / 操作 | 预期行为 |
| --- | --- |
| 插件已安装但未初始化 | 不注册业务定时器、不采集、不调用模型。 |
| 初始化后且 DSH 运行 | Host 级调度按各源 next_due 运行，与页面和会话无关。 |
| 关闭主窗口 / 隐藏 | 遵循 DSH 桌面行为；Host 存活则继续。 |
| 退出 DSH / 休眠 / 关机 | 停止或无法执行；不承诺后台在线或唤醒电脑。 |
| 再次启动 / 恢复网络 | 恢复任务与游标，合并漏掉的同源触发，只补一轮到期采集。 |
| 停用 / 卸载插件 | 停止接收新任务、关闭计时器和工作资源；不删数据。 |
| 升级 | 先完成兼容/迁移检查，再恢复；失败保留旧数据并明确阻止写入。 |

采用插件自己的持久业务队列，而非创建“请帮我抓新闻”的会话提醒。DSH Schedule 的主要合同是向会话投递消息，不具备 pg-boss 的原子入队语义。[S08、S11]

未完成任务恢复与漏跑计时合并是两件事：已有处理任务继续，不因补采重复调用模型。去重以持久任务键为准，不能只靠内存 isRunning。

关闭窗口的判断依赖目标桌面版本。官方文档存在部分旧段落，Mac/Windows 关闭、退出、升级重启的真实行为均列为发布验收，不直接承诺 UI 退出提示会识别本插件计时器。[S12]

不提供普通手动采集按钮。页面保留状态与修复入口；配置修复后调度器自动恢复，不要求用户用刷新解决故障。


## 模型选择、预算与失败恢复

### 模型路线

从 DSH 已配置目录选择一个固定 provider/model，初始化时可预选 DSH 默认路由，确认后冻结，不跟随聊天切模型。高级设置允许各步骤选择其他 DSH 路由；独立服务也先通过 DSH 支持的 Provider/凭据流程配置。[S13；S02]

每个新任务冻结模型、提示词、输入与配置版本；已在运行的请求不因用户切换配置而半途换模型。未配置 embedding 走原词面召回，有意选择向量模式却失败时不能静默切换并声称同等结果。

| 保护 | 验收要求 |
| --- | --- |
| 调用上限 | 模型和付费采集分开按服务计量；实际尝试含重试、试抓、评测。达到上限只阻塞相关任务。 |
| 有限重试 | 429 / 可恢复网络错误退避；凭据错误等待修复；格式错误有限处理；不自动换付费供应商。 |
| 回执复用 | 请求发出前留痕，成功原始响应先持久化；业务写入失败后复用响应，不重新消费。 |
| 未知结果 | 超时/崩溃可能已扣费；标记 unknown，保留进度。最多一次受控自动释放，之后人工确认。 |
| 费用展示 | 尝试次数是可执行硬上限；token/金额区分实际、估算、未知，不承诺账单金额绝不超估算。 |

技术默认：模型 20 次/分钟、200 次/小时、1,000 次/滚动24小时；每个付费采集服务 2/20/100 次。用户可调整，0=暂停，不代表无限。并发模型 2、普通采集 3、归组 1；后续依据实测调整，不改业务规则。

后台模型调用应遵守 DSH 的精确请求日志合同；不靠一次 Agent 对话跑完整流水线。日志持久化适配未通过测试前，不开放真实后台模型调用。[S13、S14]


## 数据范围、保留与清理

> 同一 DSH Home / Desktop 实例内全局共用一套热点库；不按工作区或对话复制。不同系统用户或独立 DSH Home 不自动共享。

| 数据类型 | 保留与删除 |
| --- | --- |
| 新闻 / 事实 / 事件 / 报告 | 默认长期保留，不设置自动过期删除。 |
| 信源 / 行业配置 / 收藏 / 已读 | 停用、升级、卸载不删除；重装可继续使用。 |
| 普通运行日志 | 技术默认 30 天，可修改；不包括关键任务状态与付费证据。 |
| 可重建缓存 | 技术默认 7 天，可修改；清理不等于删除原始新闻或收藏。 |
| 回执 / 未完成任务 / 未决审计 | 不能按普通日志 TTL 清理；完成后仍保留必要去重键、付费证据和请求重建材料。 |
| 用户清空数据 | 二次确认后停止任务、清空插件专属数据，回到未初始化；不触碰 DSH 聊天和共享凭据。 |

备份、恢复、导入导出、云同步均不在首版。此处“持久保留”不等于可以防止磁盘损坏、用户删除 DSH Home 或卸载整个宿主时的清理。

数据目录通过 DSH 的 Home 路径适配获取，在插件专属 data 目录中保存，不放 node_modules、应用签名资源或工作区。只允许一个写入者持有数据库，第二个 Host 连接明确只读或拒绝。

清空必须建立运行代次栅栏：旧异步请求的迟到响应不能重新写回被清空的库；清空审计提示成功前确认相关句柄已停止。磁盘空间不足暂停新写入，不自动删用户收藏“腾位置”。


## 非功能要求与安全边界

| 维度 | 规格与目标（均需实测） |
| --- | --- |
| 性能 | 10 万条摘要/索引本地基准，列表/检索 p95 < 500 ms；任务不冻结聊天 UI；查询分页上限 100。 |
| 可靠性 | 业务更新+后续入队同事务；重复触发幂等；强制终止后不丢已提交数据。 |
| 资源 | SQLite 单写入工作线程；后台请求限并发；长扫描分片或工作线程执行；不将全库常驻 Client。 |
| 安全 | 所有源内容视为不可信；HTML/Markdown 消毒；拒绝脚本协议与命令执行；外链受控。 |
| 网络 | 默认拦截私网、环回、链路本地及云元数据目标；重定向每跳复核；限定超时、响应大小、类型。 |
| 隐私 | 本地存储；仅所需正文发送给已配置服务；无插件自建遥测；凭据与带密钥 URL 不入普通日志。 |
| 可用性 | 跟随 DSH 明暗主题与键盘焦点；错误显示原因与修复位置；无结果不能伪装加载失败。 |

“本地插件”不等于离线模型。初始化前必须说明内容会发送给所选模型和采集服务。用户添加第三方信源代表配置意图，不授权内容内的指令操作本机。

正文权限沿用原 publication 语义；默认只摘要+原文链接。跨源认证重定向不得携带秘密。后台查询和 external 输入都做 Host 端 schema、长度与身份验证。

最低首批测试平台：macOS arm64、Windows x64；Mac x64 只有通过同等测试后才声明支持。桌面内置 Node 能力由启动探针实测，不按系统 PATH 中的 node 版本推断。


## 技术选型定案

| 层 | 选择 | 原因 / 边界 |
| --- | --- | --- |
| 宿主与分发 | Cordis + DSH 外部 bundle | 不 fork 官方桌面壳；一个安装入口。 |
| 语言与构建 | TypeScript / ESM；pnpm workspace；tsdown | 对齐目标 DSH 构建与发布合同，不复制源码开发环境。 |
| 界面 | DSH 共享 React 18 + Slots + UI primitives | Client 仅展示；独立业务 store 不越过官方层级。 |
| 持久化 | 插件 Store 服务 + node:sqlite 工作线程 | 关系表、索引、事务、FTS5、自有 schema 迁移；独立数据库文件。 |
| 任务 | SQLite 持久任务队列 + Host 调度器 | 业务写入与入队原子；Host 存活即运行，不依赖聊天。 |
| 模型 | ctx.llm 适配 + 严格输出 schema | 固定路由、可审计、单次请求；无自动 Agent 工具调用。 |
| 通信 | DSH 受认证的 Typert/Remote 扩展 | Host/Client 显式 DTO；不自建公开 Fastify 网站。 |
| 测试 | Vitest / Testing Library / Playwright | 单测、数据库故障注入、客户端及桌面端验收。 |

不采用“把所有关系数据塞进 DSH storageDomain”。官方该接口是 KV，无跨表事务、二级索引和通用迁移；这是经本次核对后对旧方案的修正。[S09、S10]

新建的是插件自己的可替换持久化能力与 SQLite Provider，不偷连 DSH 私有数据库、不改宿主既有 storage backend。具体 Home、Remote 和会话审计接入在 M0 编译/联调门禁验证。

首版不增加 PostgreSQL、pg-boss、Redis、Docker、独立 Node/Electron 运行时或持续在线服务器。node:sqlite/FTS5 不可用时给明确兼容错误，不自动下载未知二进制。


## 迁移阶段与开发顺序

| 阶段 | 工作 | 通过条件 |
| --- | --- | --- |
| M0 兼容性试验 | 取得完整源码与发布包；最小 bundle、页面、模型审计、SQLite/Remote 探针 | 安装/停用/重启与空草稿预填可运行；接口名来自真实类型。 |
| M1 数据与任务基础 | 关系 schema、迁移器、回执、持久队列、初始化状态机 | 断点、并发、事务、重新启用和清空栅栏测试通过。 |
| M2 完整新闻引擎 | 六类源、正文、双评分、归组、publication 与热度 | 固定输入与上游对照；失败不放行、不重复付费。 |
| M3 全部阅读与管理 | 导航、报告、主题、收藏、讨论、设置和后台评测 | 所有已确认首版核心功能可操作；不出现手动全量采集。 |
| M4 可选模块 | 模型榜、Tibo 监控、种子和方法说明 | 关闭零请求、开启正确依赖、数据保留。 |
| M5 发布验收 | 安装升级、资源压力、安全、许可、文档 | macOS/Windows矩阵、完整验收清单、发布物与源码对应。 |

顺序中的“最小可运行”是技术里程碑，不是首版减配。M3 之前不要先做精致页面来掩盖持久任务和模型适配尚未验证。

采用独立开源仓库。上游引擎按选定提交迁入，保留来源映射与许可；不复制 .env、线上数据、原品牌和无关网站发布资产。默认信源更新不自动改用户数据。

技术风险集中在 SQL 迁移、模型审计、桌面构建/动态 Client 模块，以及关闭恢复。每项有 PoC 与验收案例；失败先修适配或记录 ADR，不改成收费云后端，也不宣称已经兼容。

代码与依赖锁定必须可重现。开发期精确对齐基线 peer；不写 latest，不使用兼容豁免作为正常安装流程。[S17–S19]


## 验收摘要与发布阻断项

| ID | 关键验收 |
| --- | --- |
| AC-01 | 未初始化时抓取与模型请求数都为 0；重复初始化只导入一次。 |
| AC-02 | 18 个公开默认源完整保留；全部开启；每源首轮 8 条覆盖生效；无上游自动同步。 |
| AC-03 | 按源间隔运行；关闭页面无影响；退出无采集；重启合并漏跑。 |
| AC-04 | 双评分独立、归组后放行、手工归属不被覆盖；历史回填不制造今日热度。 |
| AC-05 | 日报不新增编辑模型请求；周/月报条目稳定、无证据导读回退。 |
| AC-06 | 固定后台模型不跟随聊天变化；达到上限局部暂停，预览/重试计入预算。 |
| AC-07 | 草稿预填不发送、不覆盖旧草稿或附件、不触发模型。 |
