# 工程目录与设置设计

## 1. 两套目录，不能混用

研发仓库 `dsh-hotstream/` 保存源码、固定行业资产与测试；运行目录位于 DSH Home 下保存本机数据。包升级可替换源码产物，不能碰用户数据库。

## 2. 依赖方向

```text
contracts ← core
contracts ← storage-sqlite
contracts + core + DSH public services ← host
contracts + DSH public UI services ← client
host + client + storage provider ← bundle
```

Client 不 import host 的 Node 实现；core 不 import DSH；Host 不 import SQLite 驱动；一个 Client 业务模块不从另一个插件运行时导出取组件。公共运行时类型来自受支持 export，不从官方仓库 src 私有路径引用。[S16]

DSH 客户端包的构建 metadata 与 Node peer 不是同一件事。不要把 Cordis inject、dsh.client.inject、dsh.client.external 混为一谈；浏览器外部模块以官方基线表为准，不在包里复制 React。开源第三方包不能保留 DSH 仓库的 workspace:* 依赖。

## 3. 运行目录（拟定路径合同）

```text
$DSH_HOME/data/hotstream/
├ hotstream.sqlite             # 唯一业务数据库
├ hotstream.sqlite-wal         # SQLite 管理，不手工删除
├ hotstream.sqlite-shm
├ runtime.lock                 # 单写入者；仅受控生命周期维护
├ audit-sessions/              # 专属辅助调用日志；M0 验证官方持久化适配
├ cache/                       # 可再生成；带 manifest 与 TTL
├ logs/                        # 普通脱敏运行日志
└ diagnostics/                 # 用户主动生成的本机诊断，不自动上传
```

这是插件自有路径选择，不声称 DSH 官方已经提供 `hotstream` 目录。DSH Home 必须通过冻结版本的公开路径服务解析；禁止硬编码用户主目录、中文用户名、OS 平台安装位置；禁止把 data 放到 `node_modules` 或 Electron ASAR。

目录首次创建最小权限；Windows 检查用户 ACL，不把 POSIX mode 当成完整 Windows 访问保证。路径解析拒绝越界和软链接删除风险。卸载包不删除此目录。DSH Home 被用户删除不在插件可保留范围内。

## 4. 设置数据模型

| 配置 | 默认 / 语义 | 来源 |
|---|---|---|
| initialized | false；仅按钮可转为已初始化 | 用户确认 |
| autoCollectEnabled | true（初始化完成后才有效） | 用户确认 |
| provider / model | 初始为空；从 DSH 选择后固定 | 用户确认 |
| stageOverrides | 空；使用固定模型；可覆盖不同处理阶段 | 用户确认 |
| embedding.mode | lexical；可选择显式 embedding | 技术默认，保留原回退能力 |
| sources.enabled | 快照首次导入全部 true | 用户确认 |
| interval_minutes | 各源快照数值 | 用户确认 |
| adaptiveFrequency | 继承基线原策略与配置；不自创统一周期 | 忠实迁移原则 |
| leaderboard / codexResetMonitor | false | 技术落地默认，能力首版保留 |
| businessTimeZone | Asia/Shanghai，v1 不随系统改刊期 | 原项目语义 + 技术定案 |
| manualCollectControl | false；无全量采集入口 | 用户确认 |
| contentRetention | keep；不自动删除内容 | 用户确认 |
| ordinaryLogDays / cacheDays | 30 / 7，可设置 | 技术默认 |
| llm attempt limit | 20/min、200/hour、1000/rolling24h | 技术保护默认 |
| paid collector limit | 每服务 2/min、20/hour、100/rolling24h | 技术保护默认 |
| concurrency | 采集3、模型2、归组1 | 技术默认 |
| backup / restore / cloudSync | false；不存在对应 UI 或 Remote | 用户明确不需要 |

配置 revision 每次保存递增。正在执行的 job 持有自己的 snapshot；后续任务才读取新版本。预算是运行时保护：用户降低上限后立即阻止新请求，不能因 job 绑定旧配置继续超额发请求。

用户的来源偏好、频率和提示词覆盖只在本地库维护；随插件升级附带的新 industry 默认文件不能回写。内置快照不是在线配置订阅。需保留 seedManifestId、installedAt 与用户来源的创建信息以解释配置出处。

## 5. 凭据与模型设置的区别

主模型：存 DSH 的 route 引用，不保存第二份 Key。用户要用新服务时跳转 DSH 已有 Provider 配置；插件高级设置再引用该 route。

SocialData、Jina、Dajiala、可选评测源和 embedding 的秘密按服务存入 DSH 支持的 Credentials 命名空间，由适配器获取。接口尚未验收之前只写 `CredentialPort` 契约，不声称存在某个未核对的 `ctx.credentials.getSecret()` 方法。前端不读回秘密，不在 JSON 模板、URL、日志里出现明文。

## 6. 配置导入不等于用户备份功能

`specs/sources.snapshot.json` 是开发/发布资产；不是产品提供的“导入备份”入口。首次初始化消费它一次。行业规范也由内置配置和本地设置编辑实现，首版不增加整个用户库的导入/导出。

## 7. 构建产物检查

交付 npm bundle / 受支持的本地包时检查：Host入口、Client入口、worker入口、生成Remote、行业prompts、locale与许可都包含；源码绝对路径不泄露；跨包版本匹配；安装在干净官方桌面环境中不需用户装 Node/Docker。

开发工具可能需要 Node/pnpm，与终端用户安装需求不同。对官方内部 cookbook 的私有 monorepo 布局只取设计参考，不逐字照搬为第三方发布清单。
